Scoring

How the grade is worked out.

Every finding that survives verification adds to a risk score from 0 to 100. Severity sets the weight and the model's confidence scales it, so one solid critical counts for more than a pile of style nits.

risk = Σ weight(severity) × confidencecapped at 100 · confidence is 0–1
  • Findings the verification pass rejects are removed before scoring.
  • Duplicates (same file and category, overlapping lines or near-identical titles) are merged, keeping the worst severity.
  • The list is ranked by severity, then confidence.

Privacy & limits

What happens to your code.

Your code

  • The code is written to a temporary folder for the scan and deleted when it ends. Only the report is saved.
  • It is sent to the model provider () for analysis. Don't paste real secrets.
  • Secrets found in your code are masked in the report, for example sk_l***tUs3.
  • Each report has a long random ID, so only people with the link can open it.
  • Reports are deleted after 24 hours. Your history is kept only in this browser.
  • Reports are kept in a local SQLite file, data/vibeaudit.db.

Limits

  • Up to or per snippet.
  • Only a couple of audits run at once. If it's busy, you'll be asked to retry in a minute.
  • Pasting the same snippet again within 24 hours returns the saved report instantly, with no model calls and no quota used.
  • Folders, GitHub repos and the Docker sandbox are only available when you run VibeAudit yourself, because they would read files or run code on the server.
  • Local mode has no hourly or daily limits, and adds folders, GitHub repos and the Deep (Docker) scan.
Good to know

What it can't promise.

  • It can be wrong. The verification pass cuts false positives, but treat every finding as a lead to check, not a verdict.
  • Results vary a little between runs. Language models aren't deterministic, so a re-run can surface a different low-severity finding.
  • A clean grade isn't a security sign-off. It means nothing obvious was found in the code it saw, not that the code is safe.
  • It only sees what you paste. A snippet has no access to the rest of your project, so bugs that depend on other files can be missed.
  • Nothing is executed. This demo reads code; it never runs it, so crashes that only show up at runtime are out of scope.
  • If the model fails, you'll know. When no code could be checked the scan ends in an error instead of a clean grade, and partly checked reports are marked incomplete.
